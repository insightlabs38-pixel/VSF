# ADR-041: Composite structures, recognition rules v3, file transfers and bulk plans

Status: accepted (B11-T03 to T06, gate G11). Code: `compiler/crates/vsf-recognizer/src/composites.rs`, `backend/execution/{files,bulk}.go`, `frontend/packages/observer` (`scrollProbe`), `tests/corpus`. Evidence: `docs/deep/evidence/VSF-B11/`.

## Context
B11-T02 left 0 of 110 annotated composite structures recognized, action effects agreeing with independent annotation for 21.5% of actions, and no way to execute a choice from a custom popup, a tab or a menu item. The first operation benchmark also dropped operations its reference driver could not confirm, which shrank the denominator exactly where the hard controls are (tabs, accordions, dialogs, menus, select menus). T03 to T05 repair both, without application-specific selectors.

## Decisions
1. **Operation accounting (T10).** The 199 operations the annotators first wrote (commit `c95c49f`, listed in `fixtures/corpus/operations.frozen.json`) are the intended-workflow denominator; none is removed. Each is classified `verified`, `recognition_limit`, `incorrect_effect`, `reference_limit`, `annotation_defect` or `information_limit`; a reviewed `operations.triage.json` may move an operation between the non-executable classes with a written reason and never changes a count. Operations the reference driver cannot confirm are still run through recognized units as a probe and never counted as verified. Reports give verified/intended and, separately, verified/reference-confirmed; the second is not coverage.
2. **Reference driver.** It acts like a person: it finds a field by its accessible name, else by the caption read beside it or the title of its header, types instead of assigning values, clicks a styled input's visible label, and picks from popups by clicking the listed entry. Text expectations count only visible text outside source listings. Steps may name a member of a composite (`item`), because the annotation grammar could not otherwise say "the second tab".
3. **Composites** are derived, not units: a pass over the observation emits `{kind, root, owner, members, covers, classifies, evidence}` for tabs, disclosure, menu, dialog, combobox popup, tree, pagination, bulk selection, sortable columns, filter bar, file input, date picker, editable cell and (from a scroll probe) virtual list. They use roles, states, `controls`/`owns` relations and the table structure; pagination is the only lexical rule and says so in its evidence. They are reported next to units and do not enter the ledger or the contract, so they cannot raise an effect claim. Unrecognizable surfaces (a popup built only on demand from unlabeled `li` elements, drag and drop) stay unrecognized.
4. **Rules v3** (`--rules 3`; v1 and v2 outputs stay frozen and byte-identical): a label that belongs to an earlier visible control no longer competes with the next control's label; `input` buttons are not text fields; a control inside a column header is named by it; fields report `editable`; actions report the words they show next to their accessible name; and structure outranks wording for the effect class: something that opens a popup reveals it, a link navigates, a tab, page or disclosure control navigates and a sort or filter control reads. Hints stay candidates; nothing here promotes a write.
5. **Execution through composites.** A step that names a composite member resolves only when exactly one recognized composite of the annotated kind has it; a `choose` on a non-native control opens it, observes again, and clicks the listed option that belongs to that owner; a control that is only a part of another hit's widget (the select a combobox enhances) is not a second choice; header and row checkboxes that share a column name resolve to the header only when the structure says so. Ambiguity still falls back, and a misbinding check compares the acted element with the reference one (a widget and its inner control count as one).
6. **Scroll probe.** `Session.scrollProbe(id)` scrolls the nearest scrollable region by one viewport and restores it; two observations of one page state show whether rows are replaced (`virtual_list`, evidence `scroll:rows_replaced`) or appended. It reads, never writes, source data, and is meant for disposable or read-only states.
7. **File transfers** (`files.go`). A transfer is described before it happens (`FileSpec`) and decided by `FilePolicy` (direction, size, media type, name); the zero policy allows nothing. `SafeFileName` is deterministic: it keeps the last path component, replaces control, bidi and filesystem-reserved characters, protects Windows device names, bounds the length, refuses names that reduce to nothing, and keeps Unicode byte-for-byte (composed and decomposed forms are different names). Names for downloads come from `Content-Disposition`, not from the file system. Bytes live in a per-session sandbox (0600, content-addressed, digest rechecked on every read); another session's reference is refused. An upload is checked against its declared size and sha256 before any request, verified against the source's listing afterwards, and a lost response after sending is `unknown`, never retried. A download is stored only if size, digest and declared length agree. A browser is handed a path only if it resolves inside the sandbox (symlinks included).
8. **Bulk plans** (`bulk.go`). A plan names records by stable id and a scope: `selected_ids`, `visible_page` (bound to the page token the person saw) or `all_matching` (bound to the filter token and the exact total). Each is re-resolved from a fresh listing before any write; stale pages, changed filters, changed counts, vanished ids and oversize plans are refused with no effect. Items run one at a time with a per-item dedup token stable across retries; only outcomes the source proved changed nothing are repeated (honoring `Retry-After`), an unknown outcome is never repeated and stops the run, and a run that changed some records and not others is `unknown` with a per-record report, never `failed`.

## Measured result (G11)
Verified operations over the frozen denominator (pre-B11 / T02 / current): development and validation 93/142, 99/142, 118/142; held-out AdminLTE and TodoMVC 34/42, 34/42, 38/42; held-out File Browser 8/15 in all three. Wrong effect and misbound stay 0. Verified over reference-confirmed is reported beside it and is not coverage. Collections found 20/37, 35/37, 36/37 on development and validation and 2/13, 2/13, 11/13 on the open held-out pages; File Browser stays 0/4. Rules 3 also reads repeated identical sibling blocks that hold their own controls, and lists of records, as collections.

## Held-out use
AdminLTE and TodoMVC held-out pages were opened for diagnosis, so they are no longer independent. File Browser stayed aggregate-only until the T06 unseal and was looked at once, page by page, after the final measurement; nothing changed afterwards. A later claim of generalization needs a new held-out set.

## Limits
- Held-out improvement is concentrated in the diagnosed applications; File Browser is unchanged in operations, collections and workflows.
- Hint false claims on the open held-out pages rose from 4 to 17, mostly read versus navigation on the same side of the write line; write seen as read-only did not rise (7 on development and validation, 1 open held-out, 0 sealed, in every build).
- Composite precision is measured only against what annotators listed; chrome the annotators excluded appears as unannotated recognized composites (98 on the development and validation pages, 15 on the open held-out pages, mostly hidden dialogs and menus of the site wrapper).
- Composite recall is measured one-to-one by kind with names preferred; names agree for fewer than half of them because annotators named structures after their purpose.
- The effect-class agreement is against annotators who were not consistent between `read` and `navigation` for sort links; the read/write line is reported separately.
- A popup built only on demand from unlabeled elements (jQuery UI autocomplete suggestions) cannot be chosen through recognized units.
- Credential fields are withheld from execution by design; operations that need one are `information_limit`, not recognizer failures.
- Duplicated native and enhanced controls that are both exposed (Choices.js text inputs) remain ambiguous.
- Browser file-name handling was tested in Chromium 141 on Linux; the saved name depends on the locale, which is why the declared name is taken from the header.

## Migration and rollback
Rules 1 and 2 outputs are byte-identical to their frozen goldens (checked by `tests/regression.rs`). The recognition document gains `composites`, `editable`, `shown` and `structural` only under rules 3. Go gains new files only. The observer gains one method. Rollback: revert the merge; nothing stored depends on it.
