# ADR-039: Authentication broker and managed sessions

Status: design accepted (B14). Whether gate G14 is accepted is recorded only in docs/deep/queue/state.json and docs/deep/reports/VSF-B14.md, never by this document. Code: `backend/auth`. Extends ADR-036 (local bridge) and ADR-037 (interfaces); uses ADR-038 (sealing, vault).

## Context
VSF acts for a person inside applications that person signs in to. B09 binds an extension runtime to an origin and B10 binds a caller to a source session, but nothing yet records how the person signed in, for which audience, until when, or what depends on it.

## Decisions
1. **A grant is a record, not a secret.** `auth.Grant` names the account, the owning caller, one source (application and exact origin), one audience, scopes, method, expiry, state and an epoch that rises on every sign-in. Secrets live only in a vault and are reached through a scoped lease. Use of a grant is checked against all of owner, origin, audience, scopes, expiry, revocation and pause; the caller sees only a generic denial, expiry or reauthentication error and the audit log records the true reason, so a probe learns nothing about other callers' grants.
2. **No assumed cross-context reuse.** Audience and origin are matched exactly (no prefix, suffix or scheme rewriting), a grant never moves to another caller or source, and a token is never passed through: VSF verifies tokens it receives against the audience it expects and never forwards a provider token to a different audience.
3. **Token verification is a fixed allow-list.** Only RS256 (2048 bits or more), ES256 (P-256) and EdDSA verify; `none`, shared-secret algorithms, critical headers, duplicate members, unknown key ids and algorithm/key mismatches are refused; issuer, audience (with `azp` when several), expiry, not-before, issued-at, nonce and maximum age are checked.
4. **The audit log is closed-vocabulary and hash-chained.** Records contain only identifiers, an origin and members of fixed sets, so they cannot carry a secret or a person's data; each line commits to the previous one. A truncated tail is a shorter valid log and needs an external anchor to detect.
5. **OAuth uses the authorization-code flow with S256 PKCE only.** State is bound to the caller, single use and ten minutes long; the token reply is limited in size, never follows a redirect and must be a Bearer token with a bounded lifetime and no scope beyond those asked for; an identity token must carry the right issuer, audience, nonce and age; when the server returns its issuer, it must match. Tokens go to the vault, never into a grant; a refused refresh ends the grant, a network failure does not.
6. **Source-managed sign-in is observed, not performed.** The person signs in on the application's own page; the paired runtime reports it, and only a sign-in the caller expected makes a grant, with no secret. A sign-in as a different person ends the earlier grant and its work. An OAuth grant never makes the source session count as signed in.
7. **Secrets are reached only through leases.** A lease is checked like any use of the grant, works for one exact origin, a few uses and at most five minutes, hands the caller a copy that is wiped when the call returns, and dies with its grant. Vaults: an encrypted file vault, and the freedesktop Secret Service through `secret-tool` with the secret on standard input; an unreachable keychain stores nothing unless a fallback was allowed on purpose. A redactor removes registered secrets, in their usual encodings, from logs, errors and streams. Native macOS and Windows stores are queued (VSF-B16-T08).
8. **VSF waits for challenges; it never answers them.** A challenge at the source pauses the grant. Only a fresh observation of the same person with nothing left to answer resumes it; a different person ends the grant; an unanswered pause or an expired grant is swept and cancels what depended on it. No method of the package accepts a code, passkey assertion or password.
9. **Profiles invalidate plans.** Roles, capabilities, locale, region, variant and application version, with the person and source, form a digest per sign-in; a plan bound to a digest stops being valid when it changes or the sign-in pauses, ends or expires. Audit records carry only a reason and the start of the digest.
10. **A person may confirm for a caller only under a delegation.** The person's interface credential confirms a request for the caller that will run it when that person has delegated to that caller (one person, one caller, thirty days at most, withdrawable). The confirmation binds the approving person, the executing caller, that caller's session and the exact request, works once, and stops working when the delegation is withdrawn; agent credentials cannot confirm for anyone, and the operation must be within the executing caller's own scopes.

## Corrections (VSF-B14-T08 to T15)
11. **The grant store is a compare-and-swap contract.** Every change is `Store.Swap(prev, next)`: it applies only if the stored revision is `prev`, raises the revision, never lets a revoked grant leave `revoked`, never lowers the epoch or secret generation, never changes the owner, source, audience, method, issuer, provider, principal or identity flag, and never widens scopes. A stale writer therefore cannot revive or widen anything. `MemStore` makes this atomic inside one process; a durable or shared store must give the same atomicity itself, and the per-grant stripe locks, refresh single-flight and dependent registry are in-process helpers, not cross-process guarantees.
12. **Precedence is revoked, then expired, then paused, then active.** Pause state (`paused_at`, `pause_until`) lives in the grant. A resume applies only to the pause and epoch it read; a newer pause survives it. Resume raises the epoch and cancels work bound to earlier epochs.
13. **Revocation is immediate; deletion may lag.** A revoked grant fails every check at once and its dependents are cancelled before any secret is touched. A secret that cannot be deleted is queued (`ErrWipePending`, `FlushWipes`, `Sweep`) and audited; it never implies the grant is usable. Refresh, revoke and cleanup serialize per grant on a stripe lock; a refresh that loses to a revocation discards its tokens, and a rotated refresh token that cannot be stored ends the grant.
14. **Observations need an authority.** `Evidence` carries the paired client (set by the transport), the bridge session, source, principal, a per-session sequence number, an observation time and optionally the epoch seen and a profile. `Browser.Verify` checks it against the bridge binding (client, owner, application, exact origin, manifest principal, runtime), a 30 second freshness window and per-session and per-source ordering, then returns an `Observation` only this package can build. Replays, older messages, a sign-in before a later sign-out, a sign-out about an older epoch, and sessions the bridge no longer vouches for change nothing. A restarted runtime continues the same grant under a new epoch. Where the bridge cannot prove a claim the result is a refusal.
15. **A session binds to one grant or none.** `Sessions` requires owner, application, exact origin, principal and runtime on the session, and a source-managed grant with a verified identity matching all of them. Zero live matches is unauthenticated (or revoked when only ended ones exist); more than one is unauthenticated and audited. Scopes come from that single grant, never a union. The session carries the grant generation (`id:epoch`).
16. **OAuth identity is explicit.** An identity token must carry a valid subject; without OpenID Connect the grant is `identity_verified=false` with no principal and fails any check that demands a proven person. The grant records a digest of the provider configuration (issuer, endpoints, client, redirect, audience, source, scopes; not keys) and a refresh must present the same one; refreshed scopes may narrow but never widen; a refreshed identity token naming another subject ends the grant. A flow keeps a snapshot of the provider it began with. Provider keys are supplied by configuration or a published key set: at most 32, RSA 2048+, P-256 or Ed25519, no key id rebound to a different key, no duplicate ids; rotation replaces the set without changing the provider's identity.
17. **Plans and confirmations are bound to the sign-in.** A profile arrives only inside verified evidence and is bound to the grant, epoch and runtime; its digest also covers application version, tenant and capability digest. A plan from an earlier epoch is invalid until `Rebind` shows the authority content is unchanged. A confirmation digest includes the session's generation, so a confirmation given before a pause, resume, runtime change or principal switch is not honoured after it; the delegation is also re-checked at use.
18. **Audit has two classes.** Mandatory records (issue, resume, lease, reveal, revoke, pause, wipe failure) either gate the effect (issue, resume, lease, reveal are undone or refused if the record cannot be written) or report `ErrAudit` after a restrictive effect that already happened, keeping the record for retry. Diagnostics (refusals, profile notes) are counted when dropped. A broker built without a log has chosen that explicitly. A file log is synced per record, cut back to its last whole line on open, refuses damage elsewhere, and rotates as one chain; removing the tail of a valid log is detectable only against an externally kept head.
19. **Secrets stay consistent.** File vault replacement is temp-sync-rename-sync-directory with cleanup of leftovers and path-free errors; the keychain adapter verifies what it stored and what it deleted; a fallback copy is removed once the primary holds the secret. Leases are snapshots that die with a refresh, epoch change, pause or revocation.
20. **Key custody.** `Keyring.Retire` fails closed unless every registered holder of sealed data (artifact store, file vault) reports no object under the version, and no tenant still writes under it; `RetireUnchecked` is the explicit destructive form. `Adopt` merges every imported version or none and refuses any conflicting key.

## Limits that remain
- All coordination here is per process. Running several workers needs a durable `Store` that satisfies the contract in decision 11, a shared pause and token-refresh owner per grant, and a shared keyring file under external locking; none of that is claimed or tested.
- The decoded-contract cache in `backend/execution` stays process-wide (VSF-B15-T06).
- The audit tail anchor, native macOS and Windows stores (VSF-B16-T08) and enterprise SAML or SCIM remain outside B14.
