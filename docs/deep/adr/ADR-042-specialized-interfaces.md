# ADR-042: Specialized interfaces: terminal and editor adapters, streams, notebooks, charts, transports

Status: accepted (B12-T01 to T06, gate G12). Code: `frontend/packages/specialized`, `backend/execution/streams.go`, `tests/specialized`. Evidence: `docs/deep/evidence/VSF-B12/`.

## Context
Terminals, code editors, notebooks, charts and realtime streams are surfaces where the source application already embeds a mature library. B12 asks to keep those libraries where they serve, to model the surrounding behavior (ownership, interruption, reconnect, kernel identity, exact data), and to fall back honestly where a surface cannot be read. Nothing here is recognized from a page yet; these are the typed models and adapters a recognized surface would be mapped to.

## Decisions
1. **Use mature libraries, behind narrow interfaces.** Terminal: xterm.js 6.0.0 with the fit addon 0.11.0 and the Unicode 11 width addon 0.9.0. Editor: CodeMirror 6 (`state` 6.7.6, `view` 6.43.13, `commands` 6.11.1). All are MIT, exact-pinned, at least two weeks old when added, and locked with integrity hashes. `TerminalAdapter` and `EditorAdapter` expose only what a controlled execution needs: write or set the value, receive exactly what the user produced, resize or select, focus, read back, dispose. Input handling, composition, grapheme movement and rendering stay the library's own.
2. **Lazy loading.** `openAdapter(kind, host, options)` imports the adapter on first use. With the page's bundler splitting (esbuild, ES modules) the entry is 9.5 KB; the terminal chunk is 437 KB and the editor chunk 581 KB, each fetched only when that adapter is opened, and a page that opens neither fetches neither. A failed chunk fetch rejects, leaves the other adapter usable, and the browser keeps the failure for that URL until the page reloads (measured), so recovery is a reload, not a retry.
3. **Terminal and editor semantics.** Lifecycle is `open` or `disposed`; every call after `dispose` throws `adapter.disposed` and disposal is idempotent and empties the host. Sizes are whole numbers within 2 to 1000 columns and 1 to 500 rows (`adapter.bad_size`). Editor ranges are UTF-16 offsets inside the document (`adapter.bad_range`). A value set from the source is reported with `userEdit: false`; read-only refuses user edits and still accepts the source's updates. Terminal output cannot retitle the page, open windows or navigate (no link, title or clipboard handler is wired). A terminal answers status queries from its output through its input like any terminal; the caller receives those bytes through `onInput` and must treat them as terminal replies, not as typing. Characters are measured with Unicode 11 widths, so wide and emoji characters take two cells; grapheme clusters joined by zero-width joiners are not merged.
4. **Streams and process ownership (Go, `Hub`/`Process`).** A process is bound to an exact `Owner` (tenant, caller, session); any other presenter learns nothing. Output frames are ordered with sequence numbers and kept in a bounded replay buffer; re-attaching after `n` replays what is still buffered and reports a hole as an explicit gap, never silently. Input is at-most-once: sequence numbers rise by one, a repeated number returns the recorded fate and sends nothing, and input that reached the process before a drop without acknowledgement is `unknown` and is never sent again. Cancel is clean only if nothing was sent; otherwise the earlier input's effect is `unknown` and says so. A re-attach to a different source session fails closed. Per-owner limits, frame limits, queued-input limits, backpressure and an idle sweep bound memory. `Hub` is not yet exposed through the HTTP or MCP interfaces.
5. **Notebook state.** A notebook document keeps, per cell, the kernel identity (id, session, epoch) that ran it. Outputs attach to the request that produced them, keep the kernel's order (a continuing stream output carries the sequence of its latest chunk), go stale on restart, and messages from an earlier epoch or session are ignored and counted. A lost connection leaves running cells `unknown`, not failed. Embedded resources are digested; script-capable MIME types are never passed on. Outputs per cell are bounded (2000 outputs, 8 MiB per resource).
6. **Charts.** A chart is modelled only from marks whose accessible names carry a label and an exact decimal string; values are never converted to floating point. The accessible alternative (`toTable`, rendered by `tableElement` with text content only) lists exactly the points the chart shows for the same filters, keeps hidden series marked, says how many points filters removed, and uses the source's text. Canvas, image, unreadable-value, duplicate-identity and over-limit (more than 100,000 marks) charts are `unsupported` with a reason and `retain_source_ui`.
7. **Transports.** A manifest declares, from evidence, which of WebSocket, SSE, WebRTC and HTTP polling a source offers, with needs, backpressure, reconnect policy, ordering and direction. `negotiate` picks the first preferred transport that the source offers and the runtime and policy allow, records why each other was skipped, and keeps the source interface when none is usable. A manifest that would buffer without bound, hides why a transport is unavailable or claims a one-way transport is bidirectional is refused. `OutboundQueue` and `planReconnect` implement the rules a client follows: sent but unacknowledged messages become unknown and are resent only if declared repeatable; attempts are finite with bounded backoff; resume is by offset only when the source supports it, otherwise the loss is reported. A reference client in `tests/specialized` exercises them against a real WebSocket server, SSE with `Last-Event-ID`, and a WebRTC data channel in Chromium.

## Measured (Chromium 141, Linux)
Terminal: 200,000 lines of output keep 1,016 rows and grow the heap by 0.6 to 1.0 MB in about 1.4 s; 2 MB of one line, 1 MB of invalid bytes, extreme cursor moves, 5,000 alternate-screen toggles and 50,000 titles leave the terminal responsive (heap growth about 0.6 MB). 40 open and dispose cycles of both adapters grow the heap by about 0.9 MB. Four runs agreed within these ranges (`docs/deep/evidence/VSF-B12/measurements.jsonl`). Editor: a 100,000-line, 3.5-million-character document is set in 30 to 90 ms, draws 67 lines and grows the heap by about 24 MB. Budgets in the tests are 16 MB, 16 MB, 8 MB and 64 MB.

## Limits
- IME is tested with synthetic composition events through the browser's input protocol, not a platform IME.
- Only Chromium 141 on Linux was run; Firefox and WebKit are not tested.
- The notebook and stream models are not connected to a live Jupyter or shell server; the Go `Hub` is tested with in-memory dialers.
- The reference reconnect client is test code; the production client is not written.
- Recognition does not yet produce these surfaces; mapping a recognized terminal, editor or chart to an adapter is later work.
- Terminal grapheme clusters joined by zero-width joiners are measured per code point.
- WebRTC is shown with a loopback data channel only; real peers, signalling and permissions are not covered.

## Migration and rollback
New package, new Go file and new CI job only; no existing contract changes. Rollback: revert the merge.
