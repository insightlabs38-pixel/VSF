# ADR-033: Verified deterministic execution

Status: accepted (B07, gate G7). Code: `backend/execution`; Rust authority: `vsf_ir::api::authorize_report`; TypeScript gate: `@vsf/wasm-host` `validate`.

## Context
B05 and B06 can say what an operation is and when it may run. B07 runs it without claiming more than the source showed: a write is Verified only after an authoritative read, and anything ambiguous stays Unknown.

## Decisions
1. **One authority for "may run".** Go and TypeScript decoders return `Unvalidated`. Rust validates the contract and checks its witnesses against the exact environment (`authorizes_execution`) through a new native-worker operation `X`; only that report mints `Authorized` (Go) or `Validated` (TypeScript, from the WASM report). Both sides must agree on the document digest. Go has no copy of the witness rules. Authorization is repeated just before the side effect.
2. **Lifecycle.** `prepared -> admitted -> running -> verified | failed | unknown`; `unknown -> verified | failed` only through reconciliation. The journal is append-only and hash-chained; replay refuses a broken chain, a gap or an illegal transition. A restart settles leftovers: running becomes `unknown/UNKNOWN_COMMIT`, earlier states become failed.
3. **Binding.** Caller scopes and entitlement, session ownership, authentication, expiry, source scopes, application, variant class, version range and the pinned contract version and digest are checked before any source contact, and again before the side effect (a revoked role stops a queued run).
4. **Preconditions.** `source_read_required` reads and compares the version the caller saw; `observation_within` bounds the age; the write is conditional on that version. A source that requires confirmation propagates it; policies that always prompt need one at admission. Confirmations are HMAC-bound to one request digest, expire, and work once.
5. **Executors and taxonomy.** Each executor reports `committed | rejected | conflict | throttled | unavailable | unknown`; transport errors after anything was sent are `unknown`. The documented-API executor and the Chromium executor (DevTools protocol, no dependency) give identical outcomes on equivalent fixtures, including the same source state.
6. **No hidden retries.** The runtime retries only outcomes the source proved changed nothing (`throttled`; `unavailable` with idempotency evidence or a dedup token), with bounds, backoff and the source's hint. Ambiguous writes are never retried, whatever the contract. The HTTP client's own replay and redirects are disabled.
7. **Distrust no-effect claims.** A `rejected` or `conflict` result is downgraded to `unknown` when a fresh read shows a new version already holding the expected values.
8. **Long tasks and cancellation.** Handles expose state and ordered progress events. Cancelling before the write is a real cancellation; during the write the result is `unknown` and the handle says the effect is unknown; after the commit the run still verifies.
9. **Locks and budgets.** Serialization follows the contract's concurrency scope (session, session and record, source). Calls per source are capped and paced; a refusal doubles the pacing interval and honours the retry hint, sustained success shortens it. Superseded in part by corrections C2 and C3.
10. **UNKNOWN_COMMIT.** A resubmitted request returns the existing operation; a new request that overlaps an unresolved write is refused until reconciliation. Superseded by corrections C2 and C4 for what may close an unresolved write.

## Corrections after review (tasks VSF-B07-T10 to T14)
C1. **Module graph.** `@vsf/wasm-host` reaches `@vsf/ir` through `validated.ts`; the smoke and bench import maps and the fixture server did not serve it, so `wasm-browser` timed out with `#status` pending. Confirmed from the page error `Failed to resolve module specifier "@vsf/ir"`. The maps and mount are fixed; a server test walks every page's static import graph against its map, and e2e tests fail with the page error, failed request or 4xx asset instead of a timeout.
C2. **Unresolved-write exclusion is atomic.** A write has a footprint (application, session, record, level). `Journal.Start` moves Admitted to Running only if no unresolved write overlaps, under the mutex every transition into Unknown also takes. `Locks` excludes overlapping footprints in arrival order and is held through the Unknown transition; the check is repeated after the lock is granted. Levels: record excludes the same record of a session; session excludes every record of a session; global source excludes the application across sessions. Overlap compares fields, never joined strings, and ids with control characters are refused. A write declaring no scope is accepted only with a freshness precondition (a conditional write), and still blocks and is blocked by unresolved writes on its record. A broken journal stops every waiting operation. Exact-request resubmission returns the existing operation and is unrelated to this exclusion. The exclusion survives restart because it is derived from the journal.
C3. **Late gate.** Caller, session, environment and the Rust validator run again immediately before the journal moves to Running, after the source read. An operation keeps the runtime, capability digest, principal and variant it was admitted under; drift is `environment_changed`. Revoked sessions are refused.
C4. **Reconciliation is evidence-graded.** The original contract is supplied by digest and the caller, a current session of the same application, variant class, principal and variant, caller scopes, source scopes, version range and the Rust validator are checked before the source is read. Levels: `proven_committed` (an operation receipt keyed to this request), `proven_not_committed` (a fenced receipt: the source will never apply it), `state_matches_unproven` (values visible, causation unproven) and `inconclusive`. Only executors whose declared capabilities support the claim can produce the proven levels. A proven commit closes as Verified only if the expected values are still visible; a state that merely matches never closes anything, and an unchanged version proves nothing. Every attempt, including refused ones, is a note on the hash chain; earlier events are never rewritten.
C5. **Non-authoritative sources.** A source whose rejections are not authoritative (the browser page) is believed to have changed nothing only if a re-read shows the same version; its throttles are not retried. For authoritative sources a matching state after a "no effect" claim is judged by values, not by version tokens.
C6. **Journal and browser.** A torn final journal line is dropped on open and truncated before the next append; event details are clipped before they can exceed the line limit. The browser executor presses only controls that are visible, enabled and not covered, with trusted input events.

## Found by running against a real browser
Chromium resends a POST when a reused connection drops; if the first attempt committed, the page reports a conflict. Go's HTTP client replays writes that carry an idempotency key. Both would have recorded a committed write as failed or hidden an ambiguity; decisions 6 and 7 are the fixes, each with a regression test.

## Limits
- The journal detects edits and gaps but not deletion of its last lines without an external anchor.
- Locks, footprints and the budget serialize one process. Nothing here excludes a second worker; distributed workers need a shared lease or fencing service before this holds across processes. Session lookup is an interface; real sessions come with pairing.
- A source without per-request receipts leaves an ambiguous write unresolved and its footprint blocked. There is no operator override yet; that decision path belongs with the version and approval workflows.
- Record scope isolates sessions; two sessions writing the same record rely on the source's conditional write.
- Form-input values are still set by script events; only the submit press uses trusted input.
- A browser plan relies on the source's own conditional write; a page that sends unconditional writes can be resent by the browser. Chromium re-sends a fetch whose connection closed before any response (seen as a second POST with the same submission id); If-Match refused it, and tests count submissions, not raw requests.
- The TypeScript brand cannot stop code in another realm that bypasses the module.

## Migration and rollback
No IR schema change. The journal gains optional `create` metadata (`app_id`, `level`, `exclusive`) and a JSON `detail` on the admitted event; an older journal opens and its unresolved writes are assumed to cover their whole session. The Go `Reconcile` signature, `Locks` API and `Capabilities` fields changed; they have no stored form. The native worker gains operation `X`; older workers answer `serve.unknown_op` and execution refuses. TypeScript and Go decoders now return `Unvalidated` (callers use `unsafe()` / `Unsafe()`). Rollback: revert the B07 merge; nothing stored depends on it.
