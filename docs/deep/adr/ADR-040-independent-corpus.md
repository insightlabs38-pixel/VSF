# ADR-040: Independent application corpus and evaluation protocol

Status: accepted (B11-T07). Code: `tests/corpus`, data: `fixtures/corpus`, results: `docs/deep/evidence/VSF-B11`.

## Context
B11 asks for coverage measured on applications nobody on this project wrote. Pages authored beside the recognizer rank the author's assumptions (see the earlier blocker packet). The owner is not required to supply the corpus; public, permissively licensed applications can be run locally.

## Decisions
1. **Sources.** Twelve applications from nine template families (after B11-T08), all pinned (40-hex git revision or release sha256), licensed (MIT, Apache-2.0, W3C) and run read-only or against disposable local state: W3C ARIA Authoring Practices examples, jQuery UI demos, Choices.js, jQuery File Upload, Tabulator, DataTables, AdminLTE 4, four TodoMVC implementations (React, Lit, jQuery, Svelte) and File Browser. Page states that need interaction are reached with scripted user-level steps recorded in the manifest.
2. **Partitions follow template families.** Applications sharing a template, component library or code base share a family and always share a partition (the manifest validator refuses otherwise): development = apg, jquery-ui, choices, blueimp-upload, tabulator; validation = datatables; held-out = adminlte, the four TodoMVC implementations, filebrowser. T01 ranks clusters on development and validation only; "held-out frequency" in the plan text is read as frequency across independent, unseen applications, and the held-out partition is measured only as an aggregate before and after the B11 changes.
3. **Seal.** Held-out annotations were committed with a sha256 per page in `fixtures/corpus/heldout.seal.json` before any recognition change. The seal is procedural plus the commit history, not secrecy: development uses `--partition dev,validation` and the held-out baseline is stored without per-page rows.
4. **Hermetic capture.** Each page is captured with the production observer in Chromium (viewport 1280x800, en-US, UTC, reduced motion). Same-origin requests are served locally; npm CDN files at a pinned version are served from a registry-verified mirror; everything else is blocked and counted. Captures reproduce: every structure digest (64 of 64 at T08) reproduced across repeated runs, with node ids excluded because a late script can shift them.
5. **Independent ground truth.** Expected structure is written by a separate agent session per batch from a dossier containing only the browser's accessibility tree, the application's name and a short description of what people do there. Annotators were told not to read any recognizer code, output or tests, and each annotation records its dossier digest, annotator id and basis. This is a different process and context from the implementer, not a different human; it is evidence tier 3 (independently annotated), not tier 4. One annotator saw a degraded DataTables capture (its jQuery was not mirrored), and one a scope rule that omitted application controls outside the main landmark; both were redone against corrected inputs.
6. **Metrics, with denominators.** Structural recall of fields, actions and collections; semantic agreement among found units (exact, coarser, unclassified, contradicted); false claims (recognized, usable units contradicted by the annotation); composite structures (dialog, menu, tabs, pagination, bulk selection, file input, date picker, tree, combobox popup, virtual list, sortable columns, filter bar, editable cell, drag and drop) recognized versus annotated; workflow coverage (all needed items found with non-contradicting semantics); unannotated recognized units reported separately and never scored; latency and memory. Executable-operation correctness is reported as not measured until supported workflows are executed against disposable state (T05, T06).
7. **Frozen dossiers.** Dossiers are committed under `fixtures/corpus/dossiers` and never regenerated implicitly, so an annotation's digest always names the exact input its annotator saw; password-like field values are withheld from them.
8. **Dropped, not hidden.** w2ui (its grid cells reach the accessibility tree empty here) and AdminLTE's calendar page (its bundle is generated on demand by the CDN) were dropped and recorded.

## Limits
Ten applications are a small public sample and say nothing about production-wide compatibility. Annotators are model sessions; disagreements between two annotators were not measured. Ground truth reflects only the accessibility tree, so controls absent from it are not annotated. Authentication-gated or private applications were not used.

## Addendum (B11-T09, B11-T10)
9. **Gaps found after T02.** The development and validation data hold no virtualized grid, no calendar or scheduling view and no server-backed site with bulk actions and pagination, and the evaluation reports executable-operation correctness as not measured. T09 adds SlickGrid (MIT, virtualized rows, checkbox selection) and Django admin (BSD-3, change lists with search, filters, pagination, bulk actions, forms, file fields; run on a disposable SQLite database) to development and FullCalendar (MIT) to validation, so the corpus reaches fifteen applications, above the guideline of eight to twelve, because each closes a named gap. Held-out is unchanged.
10. **Executable-operation protocol (T10).** An operation is annotated by a separate session from the dossier and annotation: steps name annotated items (never selectors) and expectations are page-observable (text, value, checked, row count, fragment). A reference driver, which uses only Chromium's accessibility locators and no VSF output, runs every operation first; an operation it cannot confirm is dropped and counted. The recognized-unit run then performs the same steps through units found by the recognizer alone, in a fresh page, on disposable state. Outcomes: `verified` (steps done and expectations hold), `fallback` (a needed unit is missing, unusable or ambiguous and nothing was done), `wrong_effect` (steps done, expectation fails) and `misbound` (acted on an element other than the named one). `wrong_effect` and `misbound` are false executable claims; a run with none is the condition G11 sets for "false executable claims do not increase". Held-out operations are reported as aggregates until the unseal.
11. **Queue.** T09 and T10 are correction-lane tasks that precede T03 by dependency; T03 now depends on T10.

## Addendum (B11-T10 correction, B11-T06)
12. **Frozen denominator.** Item 10's "dropped and counted" is replaced: the 199 operations written in the first annotation round (`fixtures/corpus/operations.frozen.json`, commit `c95c49f`) are the intended-workflow denominator and none is removed. Each is `verified`, `recognition_limit`, `incorrect_effect`, `reference_limit`, `annotation_defect` or `information_limit`; `operations.triage.json` records reviewed moves with a reason and never changes a count. Reports give verified/intended and, separately, verified/reference-confirmed, which is not coverage.
13. **Unseal.** At T06 the held-out partition was measured per partition with the same harness on the pre-B11, T02 and current builds. AdminLTE and TodoMVC had been opened for diagnosis and File Browser was looked at once after the final measurement, so none of the held-out set is independent for later claims.
