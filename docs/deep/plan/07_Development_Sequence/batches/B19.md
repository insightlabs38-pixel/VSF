# B19: Launch provider-agnostic billing and entitlements

**Category:** conditional outcome batch  
**Dependencies:** B15–B18  
**Goal:** Affordable local tiers, Pro localhost/cache/versioning, organizational plans, PAYG usage with spend caps; integrate provider only after selection.

## Execution steps

1. Build entitlement and consumption interfaces independent of PSP.
2. Compare merchant-of-record, PSP, invoice/bank payment options.
3. Implement signed/immutable metering event ledger with idempotency.
4. Implement rate-card versioning, refunds/credits/limits and cost preview.
5. Test downgrade/pin retention, no unauthorized cloud failover and billing reconciliation.

## Concrete artifacts

- Code, scripts, or schemas in the relevant modules with tests and pinned fixtures; versioned documentation and an evidence bundle under the batch ID.
- An explicit compatibility/security/performance delta report. Report unsupported cases, unknown outcomes, and changes to source permissions.
- A change log linking primitive/IR/contract versions and the effective source-app fixture versions.

## Acceptance and evidence

End-to-end test invoice matches meter, budgets stop safely, local extension usage not misbilled as hosted compute.

Treat listed steps as workstream hypotheses, not a locked implementation order. Split into smaller batches once failure clusters, customer needs and engineering results reveal the right granularity. Record ADRs for new shared abstractions before implementing specialist adapters.

## Stop or redirect criteria

No Stripe assumption or hard dependency.

## Batch completion handoff

Produce a single concise report with the source revision, repository commit, added/changed primitive IDs, validated operation contracts, failing/held-out tests, performance delta, security impacts, version/retention impacts, and recommendation to **PROCEED**, **HOLD**, **REVISE**, or **REVERT**.

## Research validation additions

Implement provider-neutral payment adapter selection memo with taxation, regional methods, merchant of record, invoicing, chargebacks and webhook authenticity. Test version-retention paid entitlements during downgrade, expiry, delayed payment, refund and account deletion.
