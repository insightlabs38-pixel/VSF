# B08: Build version registry, semantic diff and pins

**Category:** task-level foundational batch  
**Dependencies:** B02,B03,B07  
**Goal:** Make versioning a real system: multi-axis manifests, semantic diff, source compatibility, pinning, promotion and rollback independent of data rollback.

## Execution steps

1. Implement content-digest immutable manifest and version lineage DAG.
2. Create deterministic IR diff and classify cosmetic/additive/breaking/permission/unknown changes.
3. Compute impacted dependency closure and targeted test selection.
4. Support contract-version pin and compatibility state on source drift.
5. Implement local version storage, promotion transaction and artifact hash verification.
6. Create security revocation that overrides old pin.
7. Test old contract plus new source feature, missing required field and rollback.
8. Add draft diff result format for future Studio/CLI UI.

## Concrete artifacts

- Code, scripts, or schemas in the relevant modules with tests and pinned fixtures; versioned documentation and an evidence bundle under the batch ID.
- An explicit compatibility/security/performance delta report. Report unsupported cases, unknown outcomes, and changes to source permissions.
- A change log linking primitive/IR/contract versions and the effective source-app fixture versions.

## Acceptance and evidence

Pin→change→diff→test→promote/degrade→rollback works; source-removed operation never pretends available; data rollback not implied.

For each completed step record: test command, fixture set, expected behavior, actual behavior, performance measurements when relevant, dependency/IR change list, and rollback procedure. A passing demo alone does not close the batch.

## Stop or redirect criteria

Treat versioning as product feature from day one, not optional after initial release.

## Batch completion handoff

Produce a single concise report with the source revision, repository commit, added/changed primitive IDs, validated operation contracts, failing/held-out tests, performance delta, security impacts, version/retention impacts, and recommendation to **PROCEED**, **HOLD**, **REVISE**, or **REVERT**.
