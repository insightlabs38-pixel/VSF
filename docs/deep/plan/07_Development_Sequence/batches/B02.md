# B02: Define and validate versioned IR contracts

**Category:** task-level foundational batch  
**Dependencies:** B01  
**Goal:** Finalize schema authority, typed IDs, evidence, uncertainty, authorization, effects and version axes. Create multi-language generated bindings and semantic migration fixtures.

## Execution steps

1. Specify EnvironmentCapabilityManifest, ObservationIR, SemanticIR, OperationContract, PresentationIR, VersionManifest.
2. Define unknown/conflict and effect taxonomy with conservative defaults.
3. Build deterministic canonical encoding and hash fixtures, including UTF-8/decimal/time cases.
4. Generate TS/Go/Rust bindings and round-trip interoperability tests.
5. Describe application tenant/role/locale/source-variant identity.
6. Draft compiler/primitive/contract/runtime/source/presentation version matrix.
7. Add compatibility/test witnesses to operation contract model.
8. Author schema compatibility and promotion policy ADR.

## Concrete artifacts

- Code, scripts, or schemas in the relevant modules with tests and pinned fixtures; versioned documentation and an evidence bundle under the batch ID.
- An explicit compatibility/security/performance delta report. Report unsupported cases, unknown outcomes, and changes to source permissions.
- A change log linking primitive/IR/contract versions and the effective source-app fixture versions.

## Acceptance and evidence

Two-language encode/decode round trip preserves semantics; incompatible schemas fail closed; source permission not implied by schema artifact.

For each completed step record: test command, fixture set, expected behavior, actual behavior, performance measurements when relevant, dependency/IR change list, and rollback procedure. A passing demo alone does not close the batch.

## Stop or redirect criteria

Do not allow large primitive implementation until this has integration signoff.

## Batch completion handoff

Produce a single concise report with the source revision, repository commit, added/changed primitive IDs, validated operation contracts, failing/held-out tests, performance delta, security impacts, version/retention impacts, and recommendation to **PROCEED**, **HOLD**, **REVISE**, or **REVERT**.
