# B05: Build semantic recognition and evidence engine

**Category:** task-level foundational batch  
**Dependencies:** B03,B04  
**Goal:** Implement indexed deterministic matching over compact ObservationIR with provenance, dependency invalidation and explicit ambiguity outcomes.

## Execution steps

1. Create feature bitset/inverted index; test against naive full-scan baseline.
2. Implement structural relationships, field/label binding and operation hypothesis pipeline.
3. Add evidence ledger with claim-level provenance.
4. Build dependency graph and incremental invalidation closure.
5. Implement lexical/structural/role candidate matching without using model calls.
6. Produce UNKNOWN and CONFLICTED when semantics cannot be demonstrated.
7. Support protocol evidence reconciliation with UI evidence in fixture.
8. Demonstrate primitive fix helping two independent held-out apps.

## Concrete artifacts

- Code, scripts, or schemas in the relevant modules with tests and pinned fixtures; versioned documentation and an evidence bundle under the batch ID.
- An explicit compatibility/security/performance delta report. Report unsupported cases, unknown outcomes, and changes to source permissions.
- A change log linking primitive/IR/contract versions and the effective source-app fixture versions.

## Acceptance and evidence

Held-out apps with different frameworks recognize common form/grid classes with no vendor-specific conditions; no false high-confidence bindings in adversarial fixtures.

For each completed step record: test command, fixture set, expected behavior, actual behavior, performance measurements when relevant, dependency/IR change list, and rollback procedure. A passing demo alone does not close the batch.

## Stop or redirect criteria

If match ambiguity frequent, favor extra evidence or original surface rather than speculative selection.

## Batch completion handoff

Produce a single concise report with the source revision, repository commit, added/changed primitive IDs, validated operation contracts, failing/held-out tests, performance delta, security impacts, version/retention impacts, and recommendation to **PROCEED**, **HOLD**, **REVISE**, or **REVERT**.
