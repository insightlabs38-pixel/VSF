# B16: Build desktop and premium localhost service

**Category:** conditional outcome batch  
**Dependencies:** B09,B14  
**Goal:** Portable desktop UI and persistent authenticated loopback API/MCP gateway with premium entitlement.

## Execution steps

1. Evaluate lightweight desktop shell against browser+companion.
2. Build installers/updaters and credentials lifecycle for target OS.
3. Introduce persistent local API/MCP gated by product entitlement.
4. Test offline startup, keychain errors, OS suspend/resume and revoke.

## Concrete artifacts

- Code, scripts, or schemas in the relevant modules with tests and pinned fixtures; versioned documentation and an evidence bundle under the batch ID.
- An explicit compatibility/security/performance delta report. Report unsupported cases, unknown outcomes, and changes to source permissions.
- A change log linking primitive/IR/contract versions and the effective source-app fixture versions.

## Acceptance and evidence

Distinct demo of free extension vs paid persistent localhost service, no security regression, source UI fallback works.

Treat listed steps as workstream hypotheses, not a locked implementation order. Split into smaller batches once failure clusters, customer needs and engineering results reveal the right granularity. Record ADRs for new shared abstractions before implementing specialist adapters.

## Stop or redirect criteria

Expand OS platforms only after native capabilities/installer tests.

## Batch completion handoff

Produce a single concise report with the source revision, repository commit, added/changed primitive IDs, validated operation contracts, failing/held-out tests, performance delta, security impacts, version/retention impacts, and recommendation to **PROCEED**, **HOLD**, **REVISE**, or **REVERT**.
