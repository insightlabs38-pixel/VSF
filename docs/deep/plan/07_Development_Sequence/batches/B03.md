# B03: Build primitive registry and conformance harness

**Category:** task-level foundational batch  
**Dependencies:** B02  
**Goal:** Transform 924 candidate catalog into typed, dependency-aware requirements registry. Implement codegen/conformance harness, not 924 stubs disguised as features.

## Execution steps

1. Import and classify all 924 catalog entries as atomic/composite/adapter/service.
2. Assign stable ownership, dependencies and required evidence/test semantics.
3. Define primitive registration interface and negative-match semantics.
4. Implement graph closure verification and cycle detection.
5. Create isolated positive/negative fixture generation format.
6. Add coverage dashboard by maturity, source app and source-operation count.
7. Build signed/versioned package manifest and primitive digest.
8. Demonstrate two reusable compositions with independently tested inputs.

## Concrete artifacts

- Code, scripts, or schemas in the relevant modules with tests and pinned fixtures; versioned documentation and an evidence bundle under the batch ID.
- An explicit compatibility/security/performance delta report. Report unsupported cases, unknown outcomes, and changes to source permissions.
- A change log linking primitive/IR/contract versions and the effective source-app fixture versions.

## Acceptance and evidence

Catalog parses, all records classified or tagged UNRESOLVED, graph has no accidental dependency cycles; tests fail if implemented claim lacks witness.

For each completed step record: test command, fixture set, expected behavior, actual behavior, performance measurements when relevant, dependency/IR change list, and rollback procedure. A passing demo alone does not close the batch.

## Stop or redirect criteria

Rule: test coverage rather than number of registry names.

## Batch completion handoff

Produce a single concise report with the source revision, repository commit, added/changed primitive IDs, validated operation contracts, failing/held-out tests, performance delta, security impacts, version/retention impacts, and recommendation to **PROCEED**, **HOLD**, **REVISE**, or **REVERT**.
