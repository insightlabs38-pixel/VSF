# B04: Implement browser observation and incremental events

**Category:** task-level foundational batch  
**Dependencies:** B02,B03  
**Goal:** Capture controlled DOM/AX/layout/URL/Mutation and origin-scoped observation epochs with appropriate permissions. Establish stale/missing evidence behavior.

## Execution steps

1. Implement document/frame/shadow-root enumerators including opaque boundaries.
2. Capture role/name/labels and selected geometry lazily.
3. Implement mutation batching with sequence IDs and missing-event resync.
4. Track locale, viewport and feature flags where observable.
5. Mark source scopes and redact likely sensitive text before diagnostics.
6. Define schema for source protocol/API evidence rather than undocumented traffic.
7. Build stable fixture runner across SPA and traditional multi-page navigation.
8. Report collector CPU/RSS and cold/steady-state overhead.

## Concrete artifacts

- Code, scripts, or schemas in the relevant modules with tests and pinned fixtures; versioned documentation and an evidence bundle under the batch ID.
- An explicit compatibility/security/performance delta report. Report unsupported cases, unknown outcomes, and changes to source permissions.
- A change log linking primitive/IR/contract versions and the effective source-app fixture versions.

## Acceptance and evidence

Fixture updates reconcile without full scan for small changes; inaccessible frame not fabricated; unsafe observation is blocked; no user content sent to cloud in local mode.

For each completed step record: test command, fixture set, expected behavior, actual behavior, performance measurements when relevant, dependency/IR change list, and rollback procedure. A passing demo alone does not close the batch.

## Stop or redirect criteria

Capture capability differs by runtime: advertise limits.

## Batch completion handoff

Produce a single concise report with the source revision, repository commit, added/changed primitive IDs, validated operation contracts, failing/held-out tests, performance delta, security impacts, version/retention impacts, and recommendation to **PROCEED**, **HOLD**, **REVISE**, or **REVERT**.
