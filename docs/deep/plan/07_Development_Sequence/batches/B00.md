# B00: Build foundation and reproducible validation

**Category:** task-level foundational batch  
**Dependencies:** None  
**Goal:** Implement toolchain-pinned monorepo; establish licensing/security notices; initialize Rust crates, TS packages and Go modules; create reference source applications; import the baseline capability JSON and gap register; define ADR workflow and CI paths.

## Execution steps

1. Create pinned Rust/Go/Node version manifest and lockfiles.
2. Build an empty cross-language schema integration smoke test.
3. Set up Playwright synthetic source app and minimal WASM smoke fixture.
4. Add deterministic golden fixtures and secret-free test logs.
5. Configure lints, formatting, supply-chain scans, dependency review, reproducible artifact digest.
6. Implement CI matrix with mandatory artifacts and failure summaries.
7. Create evidence bundle template for every subsequent batch.

## Concrete artifacts

- Code, scripts, or schemas in the relevant modules with tests and pinned fixtures; versioned documentation and an evidence bundle under the batch ID.
- An explicit compatibility/security/performance delta report. Report unsupported cases, unknown outcomes, and changes to source permissions.
- A change log linking primitive/IR/contract versions and the effective source-app fixture versions.

## Acceptance and evidence

Clean clone reproducibly builds native and WASM compiler stubs plus Go/TS; no unpinned generated dependencies; fixture app runs; CI catches deliberate failure.

For each completed step record: test command, fixture set, expected behavior, actual behavior, performance measurements when relevant, dependency/IR change list, and rollback procedure. A passing demo alone does not close the batch.

## Stop or redirect criteria

Research gate: dev environment complexity must remain controlled; no application-specific hacks.

## Batch completion handoff

Produce a single concise report with the source revision, repository commit, added/changed primitive IDs, validated operation contracts, failing/held-out tests, performance delta, security impacts, version/retention impacts, and recommendation to **PROCEED**, **HOLD**, **REVISE**, or **REVERT**.
