# B10: Expose API, CLI and MCP vertical slice

**Category:** task-level foundational batch  
**Dependencies:** B07,B08,B09  
**Goal:** Generate interfaces from a single verified operation; no hand-implemented business logic per surface.

## Execution steps

1. Define API error taxonomy, contract version routing, OpenAPI doc generation.
2. Implement Go CLI typed argument grammar, structured output and version pin flag.
3. Implement minimal MCP tools/resources with protocol version negotiation.
4. Authenticate each caller separately, enforce source context at runtime.
5. Add lazy namespaced tool discoverability and stable ordering.
6. Cross-check effect results/unknown status across UI/REST/CLI/MCP.
7. Test client older contract, bad arguments, revoked source role and long-running task fallback.
8. Measure per-layer dispatch overhead excluding source.

## Concrete artifacts

- Code, scripts, or schemas in the relevant modules with tests and pinned fixtures; versioned documentation and an evidence bundle under the batch ID.
- An explicit compatibility/security/performance delta report. Report unsupported cases, unknown outcomes, and changes to source permissions.
- A change log linking primitive/IR/contract versions and the effective source-app fixture versions.

## Acceptance and evidence

One operation from same contract succeeds through all four surfaces; breaking source change degrades appropriately; no invented high-level API for unverified behavior.

For each completed step record: test command, fixture set, expected behavior, actual behavior, performance measurements when relevant, dependency/IR change list, and rollback procedure. A passing demo alone does not close the batch.

## Stop or redirect criteria

Do not expand endpoint counts without shared semantics and tests.

## Batch completion handoff

Produce a single concise report with the source revision, repository commit, added/changed primitive IDs, validated operation contracts, failing/held-out tests, performance delta, security impacts, version/retention impacts, and recommendation to **PROCEED**, **HOLD**, **REVISE**, or **REVERT**.

## Research validation additions

Pin core `2026-07-28` protocol conformance; test JSON Schema 2020-12, tool namespace stability/collisions, cached discovery and optional Tasks extension negotiation. Never require Tasks from clients that do not advertise it.
