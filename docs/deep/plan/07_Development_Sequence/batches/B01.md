# B01: Validate browser and language boundaries

**Category:** task-level foundational batch  
**Dependencies:** B00  
**Goal:** Spike extension MV3/Chrome policies, CDP and Playwright capture, local bridge, TS↔Rust WASM IPC, alternate WebDriver BiDi probe. Measure real serialization and lifecycle behavior before fixing interfaces.

## Execution steps

1. Build a packaged extension that can read permitted basic DOM snapshot.
2. Demonstrate permissions origin-by-origin and prevent page-origin misuse.
3. Observe MV3 service worker teardown/restart and preserve no sensitive secrets in global state.
4. Pass compact typed arrays between TS and Rust/WASM with repeatable hashes.
5. Benchmark capture versus parse versus transport, including 1k/10k/50k nodes.
6. Compare Node/browser/Go boundary options for native compiler execution.
7. Prototype isolated service bind with origin/CSRF/rebinding check.

## Concrete artifacts

- Code, scripts, or schemas in the relevant modules with tests and pinned fixtures; versioned documentation and an evidence bundle under the batch ID.
- An explicit compatibility/security/performance delta report. Report unsupported cases, unknown outcomes, and changes to source permissions.
- A change log linking primitive/IR/contract versions and the effective source-app fixture versions.

## Acceptance and evidence

Chrome MV3 policy design review; Rust native and WASM canonical results equal on sample data; subcomponent latency breakdown recorded; no secret leak.

For each completed step record: test command, fixture set, expected behavior, actual behavior, performance measurements when relevant, dependency/IR change list, and rollback procedure. A passing demo alone does not close the batch.

## Stop or redirect criteria

If MV3 remotely supplied plans violate policy, define a restricted data contract or move interpreter to companion; do not silently ignore.

## Batch completion handoff

Produce a single concise report with the source revision, repository commit, added/changed primitive IDs, validated operation contracts, failing/held-out tests, performance delta, security impacts, version/retention impacts, and recommendation to **PROCEED**, **HOLD**, **REVISE**, or **REVERT**.

## Research validation additions

Exercise 30-second idle worker termination, verify checkpoint recovery, measure native-messaging message limits and document the policy classification of each extension artifact format.
