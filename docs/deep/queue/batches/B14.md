### VSF-B14-T06 · Let a person confirm in the user interface a request an agent caller will run

### VSF-B14-T08 · Atomic grant lifecycle: revisioned compare-and-swap store, terminal revocation, immediate revoke with retried cleanup

- **Depends:** VSF-B14-T07; correction lane, ADR-039.
- **Done when:** Grants change only through compare-and-swap; revocation wins over refresh, pause, resume and expiry; revoked grants never revive; refresh is single-flight and cannot resurrect revoked credentials; failed deletion never leaves a credential authorized.
- **Verification:** positive: store contract, refresh racing revoke, refresh racing refresh with strict rotation, stale resume against newer pause, storage failures at each transition. Adversarial: stale writer revives, widens or retargets a grant; revoke between refresh check and commit; tokens stored by a lost race; delete failure.
- **Evidence:** `docs/deep/evidence/VSF-B14/` run logs and `docs/deep/queue/receipts/VSF-B14-T08.json`.

### VSF-B14-T09 · Exact session-to-grant binding

- **Depends:** VSF-B14-T08; correction lane, ADR-039.
- **Done when:** A source session is bound to exactly one verified grant by caller, application, exact origin, principal and runtime; absent, ambiguous, stale, revoked or inconsistent identity fails closed; scopes come from the one bound grant.
- **Verification:** positive: bound session, two origins and two people, concurrent sign-ins leave one live grant. Adversarial: empty principal/origin/runtime, other origin or principal, two live grants in any store order, OAuth or unverified grants.
- **Evidence:** `docs/deep/evidence/VSF-B14/` run logs and `docs/deep/queue/receipts/VSF-B14-T09.json`.

### VSF-B14-T10 · Validated observation authority for source-browser evidence
